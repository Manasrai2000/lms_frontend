# LMS Dynamic Navigation Menu & Module Specification

Document specification for `GET /api/v1/auth/my-menu` API and complete Frontend-Backend Menu Schema.

---

## 1. Overview & Architecture

System mein 3 Core Layers hain:
1. **User Role**: `ADMIN` | `TEACHER` | `STUDENT`
2. **Module Permissions & Books Permissions**:
   - `ADMIN` → Can assign Books & Modules to `TEACHER` or `STUDENT`.
   - `TEACHER` → Can assign Books & Modules **ONLY** to their assigned `STUDENTS` (Condition: `Student Permissions ⊆ Teacher Permissions`).
   - `STUDENT` → Receives granted subset of books & modules (No permission management menu).
3. **Dynamic Menu API (`GET /api/v1/auth/my-menu`)**:
   - Reads JWT Bearer Token.
   - Identifies User ID & Role.
   - Merges Role Defaults + Granted `user_module_permissions`.
   - Returns exact allowed menu items for Next.js Sidebar rendering.

## 4. Permission Logic Rules for Backend Enforcement

1. **Hierarchy Rule**:
   - `Student Granted Permissions ⊆ Teacher Granted Permissions ⊆ Admin Master Modules`
   - Agar Teacher ke paas `Current Affairs` ya `Test Generator` permission nahi hai, to Teacher use Student ko grant nahi kar sakta.

2. **Database Relationships**:
   - `modules` (id, key, title, route, icon, role_access, sort_order)
   - `user_module_permissions` (id, user_id, module_id, granted_by_user_id, is_granted)
   - `user_book_permissions` (id, user_id, book_id, granted_by_user_id, is_granted)

3. **Frontend Integration**:
   - Frontend initial layout mount par `GET /api/v1/auth/my-menu` call karega aur direct response JSON parse karke sidebar dynamically generate karega.
